Tennis score mapping to IPTC SportsML

How does the Live Tennis API score object map to IPTC SportsML? Each field of the Score object is listed with the SportsML 3.1 element or attribute it becomes, or with no direct equivalent. Every SportsML name links to IPTC's documentation. A worked example and six synthetic fixtures show the mapping in real files.

Mapped against IPTC SportsML 3.1 as published on iptc.org, read on 2026-11-15. Fixtures under CC BY 4.0.

Which SportsML version does this map to?

The mapping uses SportsML 3.1, the newest version on iptc.org. IPTC released it in June 2019. The tennis part of the standard is a plugin schema, sportsml-specific-tennis.xsd, which the main schema includes. Both files carry IPTC's CC BY 4.0 notice.

The mapping was read from the schema files, the tennis plugin documentation, the core schema documentation and IPTC's own tennis example. It is our reading. IPTC has not reviewed it.

Our own comparison of tennis score notation formats sets SportsML beside three other formats.

How does each Score field map to SportsML?

The rows follow the Score schema in the spec, every field in its order. Each SportsML name links to the section of IPTC's documentation that defines it.

Each Score field and the SportsML 3.1 element or attribute it maps to
Score fieldSportsML 3.1Notes

sub-score/@score		One stats-tennis-set per set and player. IPTC's example also writes the same numbers as sub-score. SportsML has no match tie-break, so the fixtures write one as a set won 1-0, with its points in score-tiebreaker.
pointsaction/@server-score

event-metadata-tennis/@receiver-score		On an action and on event-metadata-tennis the game score is ordered by server, and ours by player. 0 becomes love and AD becomes ad. The fixtures write 40-40 as 40 and 40, though the list also has deuce. A tie-break count has no code, so tie-break points carry no game score.
serverevent-metadata-tennis/@server-idref

participant/@role		server-idref exists only on event-metadata-tennis. On an action the server is a participant with a role. IPTC publishes no tennis role codes, so the fixtures use ltapirole:server. A null server leaves the attribute out.
is_tiebreakNo direct equivalentNo attribute says the current game is a tie-break. score-tiebreaker gives a set's tie-break points, but not whether the breaker is still being played.

win_probability_metaNo direct equivalentThe model version and the time the two probabilities were made.
timestampNo direct equivalentOur clock, refreshed while a source keeps sending the same state. action/@date-time is when the play took place on court, which this field never claims. last-modified is closest, but a state sent again is not a change to the record.
accepted_ataction/@createdThe instant we accepted the state, stamped once. IPTC describes created as the time the action record was made.

verdictNo direct equivalentWhy a read is not the newest state we judged, for example a withdrawn state.

Read the arrays the usual way. sets, games and points put player 1 first and player 2 second.

Which match and point fields does SportsML cover?

A SportsML match document also says who played, how the match ended and what happened on each point. These fields come from the Match, LivePoint and HistoryTapeRow schemas.

Worked example: a match decided by a match tie-break

Player A and Player B are synthetic. They split the first two sets 6-4 and 4-6. A ten-point match tie-break replaces the third set and Player A wins it 10-8.

These are the last two score states, at 9-8 in the breaker and after the match point. The deciding set's slot holds the breaker's points while it is played. The last state shows the match over.

[
  {"sets": [1, 1], "games": [[6, 4, 9], [4, 6, 8]], "points": ["9", "8"], "server": 1, "is_tiebreak": true, "timestamp": "2026-01-05T10:11:20Z", "accepted_at": "2026-01-05T10:11:20Z", "sequence": 318},
  {"sets": [2, 1], "games": [[6, 4, 10], [4, 6, 8]], "points": ["0", "0"], "server": null, "is_tiebreak": false, "timestamp": "2026-01-05T10:12:00Z", "accepted_at": "2026-01-05T10:12:00Z", "sequence": 319}
]

The same match as a SportsML document. The third set is written as a set won 1-0, with the breaker's points in score-tiebreaker. The action is the match point.

<?xml version="1.0" encoding="UTF-8"?>
<!-- SYNTHETIC tennis scoring fixture. No real players, matches or results.
     Fixture: 02-match-tiebreak. Licence: CC BY 4.0, https://creativecommons.org/licenses/by/4.0/
     From the Live Tennis API SportsML fixtures, https://github.com/livetennisapi/openapi/tree/main/examples/sportsml -->
<sports-content xmlns="http://iptc.org/std/nar/2006-10-01/">
  <sports-metadata doc-id="ltapi-synthetic-02-match-tiebreak" date-time="2026-01-05T10:12:00Z" language="en">
    <catalogRef href="http://www.iptc.org/std/catalog/catalog.IPTC-Sports_1.xml"/>
    <sports-title>Synthetic fixture: match tie-break to ten</sports-title>
  </sports-metadata>
  <sports-event>
    <event-metadata event-status="speventstatus:post-event">
      <event-metadata-tennis number-of-sets="3"/>
    </event-metadata>
    <player id="p1">
      <player-metadata><name>Player A (synthetic)</name></player-metadata>
      <player-stats score="2" event-outcome="speventoutcome:win">
        <player-stats-tennis>
          <stats-tennis-set set-number="1" score="6"/>
          <stats-tennis-set set-number="2" score="4"/>
          <stats-tennis-set set-number="3" score="1" score-tiebreaker="10"/>
        </player-stats-tennis>
      </player-stats>
    </player>
    <player id="p2">
      <player-metadata><name>Player B (synthetic)</name></player-metadata>
      <player-stats score="1" event-outcome="speventoutcome:loss">
        <player-stats-tennis>
          <stats-tennis-set set-number="1" score="4"/>
          <stats-tennis-set set-number="2" score="6"/>
          <stats-tennis-set set-number="3" score="0" score-tiebreaker="8"/>
        </player-stats-tennis>
      </player-stats>
    </player>
    <actions>
      <!-- 17 earlier points, one action each, are in the fixture file -->
      <action type="sptenaction:point" sequence-number="319" created="2026-01-05T10:12:00Z" set="3" game="1">
        <participant idref="p1" role="ltapirole:server"/>
        <participant idref="p2" role="ltapirole:receiver"/>
        <participant idref="p1" role="ltapirole:point-winner"/>
      </action>
    </actions>
  </sports-event>
</sports-content>

The Score schema says a finished match tie-break is often published as a one-game set, 1-0. The fixture keeps the breaker's points in that slot instead. Take the winner from sets either way.

Test fixtures for tennis scoring edge cases

The examples/sportsml folder holds six synthetic matches. No player, match or result in them is real. Each fixture is two files. One is the sequence of score states as JSON. The other is the same match as a SportsML document. The fixtures are under CC BY 4.0.

The six synthetic fixtures and what each covers
FixtureWhat it coversStatesFiles
Deciding-set tie-break at six allThe third set reaches 6-6 and a seven-point tie-break decides it, 9-7.17JSON SportsML
Match tie-break to tenA ten-point match tie-break replaces the third set and ends 10-8.19JSON SportsML
No-ad gamesTwo games reach 40-40. One deciding point is a break and the other wins the match.15JSON SportsML
RetirementPlayer B retires serving at 15-30 in the second set.4JSON SportsML
WalkoverPlayer A withdraws before a ball is struck, so the fixture has no score states.0JSON SportsML
DefaultPlayer A is defaulted while serving at advantage Player B, after deuce, in the second set.8JSON SportsML

The folder's check script validates every SportsML document against the IPTC schema. It replays each point from the first JSON state with the rules of tennis and compares every state. It also compares the result and the way the match ended.

pip install lxml
python examples/sportsml/check_fixtures.py

The IPTC schema files are vendored unchanged, with their CC BY 4.0 notice and source address. The script refuses to run if one differs from its pinned SHA-256.

Where does SportsML 3.1 leave tennis open?

Writing the fixtures needed a choice in each of these places. Each one is in the published files.

  • No match tie-break. score-tiebreaker is documented as an integer, generally 0 through 7. Nothing says how to write a ten-point breaker that replaces a set.
  • No scoring format. No attribute says a match uses no-ad games, a final-set tie-break or a match tie-break.
  • No code for a tie-break count. The sptengameresult codes are love, 15, 30, 40, game, ad and deuce, so a tie-break point has no score.
  • No tennis role codes. An action names the server through a participant role, and IPTC's example uses vendor codes for it. server-idref exists only on event-metadata-tennis.
  • One score, two types. server-score takes a code on an action and a plain value on event-metadata-tennis. set and game are integers on an action and strings there.
  • No retirement or default. The event status list has forfeited, and the only status reason is withdrawal. The nearest outcome type for a default is authority-decision.
  • Set score wording. The annotation on stats-tennis-set/@score reads "Either love, 15, 30, 40, or game". IPTC's own example puts the games won there.
