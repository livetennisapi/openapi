Live Tennis API tools for the Vercel AI SDK

How do you give a Vercel AI SDK model live tennis data? Install livetennisapi-ai and pass livetennisTools() to generateText. The model gets 24 read-only tools for live scores, players, fixtures, rankings, head-to-head, the results archive and model win probability.

Package livetennisapi-ai 1.1.0, for ai v7. Tested with ai 7.0.148 on 2026-10-22. Free keys need no card.

Install

The package is livetennisapi-ai on npm. It needs Node 18 or later. ai v7 is a peer dependency, so the tools use the copy your app already has.

npm install livetennisapi-ai ai
pnpm add livetennisapi-ai ai
yarn add livetennisapi-ai ai
bun add livetennisapi-ai ai

Set the API key

The tools read your key from the LIVETENNISAPI_KEY environment variable. Get a free key. No card is needed.

export LIVETENNISAPI_KEY=twjp_...

You can also pass the key in code as livetennisTools({ apiKey }). The apiKey option wins over the environment variable. Each call returns a tool set bound to one key, so one process can serve users on different plans.

Call the tools from generateText

Pass the whole set as tools. This example goes through the AI Gateway, which reads AI_GATEWAY_API_KEY. Any other AI SDK model works in its place.

import { generateText, gateway, isStepCount } from 'ai';
import { livetennisTools } from 'livetennisapi-ai';

const { text } = await generateText({
  model: gateway('openai/gpt-5-mini'),
  prompt: 'Which tennis matches are live right now, and what are the scores?',
  tools: livetennisTools(), // reads LIVETENNISAPI_KEY
  stopWhen: isStepCount(3),
});

console.log(text);

The SDK runs each tool the model picks and hands the result back. isStepCount(3) leaves room for a tool call and then the answer.

Send only the tools you need

Each tool is also exported on its own. Every tool's description and input schema go to the model on every request, so a smaller set costs fewer tokens.

import { getLiveMatches, getMatchScore } from 'livetennisapi-ai';

const apiKey = process.env.LIVETENNISAPI_KEY;

const tools = {
  get_live_matches: getLiveMatches({ apiKey }),
  get_match_score: getMatchScore({ apiKey }),
};

check_api_status tells the model which plan the key is on. That is the quickest way to find out why another tool declined. Plans and prices are on the pricing page.

What a tool returns

A successful call returns ok: true, a readable message and the data. A missing key, a plan limit, a rate limit or an empty result returns ok: false. The message says what to do next.

{
  ok: false,
  message: 'This data requires the ULTRA plan, and the configured API key is on a lower tier. ...'
}

None of these throw. The model reads the message and can pass the upgrade path or the wait time on to the user.

From an MCP client

The same 24 tools also run as an MCP server. The hosted endpoint is https://mcp.livetennisapi.com/mcp. To run it yourself, use npx livetennisapi-mcp from livetennisapi/livetennisapi-mcp.
